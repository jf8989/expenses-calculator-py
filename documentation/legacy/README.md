# Legacy Documentation

This folder retains completed, superseded, abandoned, or historical documents for provenance. It is not deferred work and its contents are not expected to become active again.

**Agent contract: this folder is immutable and opaque during normal work.** Do not index, scan, or read its contents unless the operator or an active document points to a specific file, or an approved workflow is retiring material into it. Never treat legacy text as current product truth without verifying it against current code and documentation.

Use `documentation/backlog/` for “not now, but still eligible to return.” Use `legacy/` for “no longer active; preserve only for history.” Do not create parallel `archive/`, `done/`, or `old/` folders.

Keep the folder shallow. A complete superseded, completed, or abandoned plan package goes under `legacy/plans/{slug}/` with the master, every linked detail file, its final status, reason, source plan, and supersession relationship intact.

## Reuse rule

Legacy material is not directly reactivated. First verify it against current truth. If it becomes valid scope again, record a new operator decision, assign current stable IDs as needed, and enter it through a new or safely amended active plan without changing the legacy record.
